Problem

Where does AlphaFold spend time on CPU, GPU, and TPU? Same model config, script, and input shape; measure init, first predict (compile + run), steady-state. Hardware: Colab CPU/T4; Stanford TPU v5e-8 (2×4).

One script spike_tpu_forward_pass.py → CPU (result_cpu.json), GPU T4 (result_gpu-t4.json), TPU v5e-8 (result_tpu + traces). Systems timings: Haiku random init (no ~350MB weights).

Experiments — Twelve TPU follow-ups

Amber rail = negative result. Click + for method notes on the live UI.

Scaling

  1. Sequence length — 14.6× time for 8.3× length. Super-linear; swept 60–500 residues.
  2. Recycle depth — ~0.46s per extra recycle; compile flat after first.
  3. Chip visibility — 1 of 8 chips used on default path.

Bottleneck & fix

  1. Profiler trace — 76% of first call in pjit cache_miss (host JIT).
  2. Compilation cache — 6.8× faster init_params; steady-state unchanged.
  3. Precision bf16 — −40% steady-state HBM; little runtime change.

Multi-chip

  1. Multi-query batching — lower proteins/sec vs batch=1 (negative). vmap stayed on one chip.
  1. pmap — 6.92× throughput (2.13 → 14.72 proteins/sec on 8 chips).
  2. Auto-sharding GSPMD — 0× tensor split (negative); ~463 MB copy on every chip (AlphaFold ensemble is a sequential hk.while_loop).
  3. Ensemble shard — 8/8 chips via pmap + pmean on one query’s ensemble average; reduction verified; HBM 427–624 MB/chip.

Fit & rigor

  1. Empirical scaling law — R² 0.981 on 16 runs: throughput ≈ 4527.77 · chips0.963 · length−1.572.
  1. Model pick & repeats — <1% stdev; model_5 ~15% faster steady-state than model_3/4.

Cost

Headline: cost per prediction is nearly flat in chip count. Baseline path 1 of 8 chips active (~87% idle) → TPU $1.25 vs GPU $1.27 per 1k; CPU $11.19. After pmap, unit cost stays roughly constant as chips grow.
