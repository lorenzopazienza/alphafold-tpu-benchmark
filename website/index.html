Problem

Where does AlphaFold 2 spend time on CPU, GPU, and TPU? Same model config, script, and input shape (AlphaFold 2 model_3, 0 recycles, 118 residues, Haiku random-init); measure init, first predict (compile + run), steady-state. Hardware: Google Colab Intel Xeon (2 vCPU); Google Colab NVIDIA Tesla T4; Stanford GKE TPU v5e-8 (tpu-v5-lite-podslice, 2×4, 8 chips). Follow-up: AlphaFold 3 on the same Google Colab Intel Xeon CPU (2 vCPU) and Google Colab NVIDIA Tesla T4 - see #af3.

Approach

One script spike_tpu_forward_pass.py → Google Colab Intel Xeon CPU (result_cpu.json), Google Colab NVIDIA Tesla T4 (result_gpu-t4.json), Stanford GKE TPU v5e-8 / tpu-v5-lite-podslice 2×4 (result_tpu + traces). Systems timings: AlphaFold 2 model_3, Haiku random init (no ~350MB weights).

Experiments - Twelve TPU follow-ups

Amber rail = negative result. Click + for method notes on the live UI.

Scaling

  1. Sequence length - 14.6× time for 8.3× length. Super-linear; swept 60–500 residues.
  2. Recycle depth - ~0.46s per extra recycle; compile flat after first.
  3. Chip visibility - 1 of 8 chips used on default path.

Bottleneck & fix

  1. Profiler trace - 76% of first call in pjit cache_miss (host JIT).
  2. Compilation cache - 6.8× faster init_params; steady-state unchanged.
  3. Precision bf16 - −40% steady-state HBM; little runtime change.

Multi-chip

  1. Multi-query batching - lower proteins/sec vs batch=1 (negative). vmap stayed on one chip.
  1. pmap - 6.92× throughput (2.13 → 14.72 proteins/sec on 8 chips).
  2. Auto-sharding GSPMD - 0× tensor split (negative); ~463 MB copy on every chip (AlphaFold ensemble is a sequential hk.while_loop).
  3. Ensemble shard - 8/8 chips via pmap + pmean on one query’s ensemble average; reduction verified; HBM 427–624 MB/chip.

Fit & rigor

  1. Empirical scaling law - R² 0.981 on 16 runs: throughput ≈ 4527.77 · chips0.963 · length−1.572.
  1. Model pick & repeats - <1% stdev; model_5 ~15% faster steady-state than model_3/4.

AlphaFold 3 - side investigation

Separate DeepMind codebase (Pairformer + diffusion), not an AF2 version bump. Same 118-residue toy input, seed=1, trained weights (~1.15 GB), five diffusion samples per call.

Backend AF2 / sample AF3 / sample AF3 / AF2
CPU (Google Colab) 212.1s 490.8s 2.3×
GPU T4 (Google Colab) 13.1s 22.8s 1.74×

AF3 CPU→GPU speedup is 21.5× (vs AF2’s 16.2×). Interactive 3D viewer loads /structure/af3_toy_test_cpu-colab_model.cif via 3Dmol.js (same pattern as ubiquitin) plus a per-residue confidence chart. Global ptm 0.23; CA confidences roughly 23–61. Low confidence is expected for a no-MSA input - not comparable to ubiquitin mean pLDDT 90.5.

TPU negative result: Stanford v5e-8 Job built native AF3 + CCD + weights + jax[tpu], then failed flag validation: public --jax_backend only accepts cpu | gpu | mps. Not an infra miss.

Cost

Headline: cost per prediction is nearly flat in chip count. Baseline path 1 of 8 chips active (~87% idle) → TPU $1.25 vs GPU $1.27 per 1k; CPU $11.19. After pmap, unit cost stays roughly constant as chips grow.
